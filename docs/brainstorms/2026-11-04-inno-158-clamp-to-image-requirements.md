# INNO-158 이미지 밖으로 Bbox·키포인트가 나가지 않게 제한

## Summary

스켈레톤의 bbox와 키포인트, 그리고 객체 통째 이동(스켈레톤·사각형)이 이미지 경계를 넘지 못하게 한다. 경계에 닿으면 그 자리에서 "벽처럼" 멈추고, 통째 이동은 크기를 유지한다. 이미 저장된 경계 밖 데이터는 건드리지 않는다.

## Problem Frame

지금 가장 흔한 사례는 이미지 가장자리 근처에 새 스켈레톤을 그릴 때다. 새 스켈레톤의 bbox가 키포인트 범위 ±20px로 자동 생성되어 그대로 이미지 밖으로 나간다(`cvat-core/src/annotations-objects.ts`의 `SKELETON_BBOX_FALLBACK_MARGIN`). 그린 사각형이 이미지 밖까지 걸치면 키포인트 자체도 밖에 배치된다. 그 밖에도 bbox 모서리 핸들, 키포인트 드래그, 객체 통째 드래그로 경계를 넘을 수 있다.

편집 반영 시 보정도 일관되지 않다. 좌표가 바뀌는 편집이 반영될 때마다 `fitPoints`가 좌표를 이미지 안으로 자르지만, 스켈레톤 요소(키포인트)·회전 도형·타원·큐보이드는 건너뛴다. bbox는 이 보정을 거치지 않는다. 반대로 사각형은 점마다 잘리기 때문에, 가장자리로 끌고 간 사각형은 놓는 순간 크기가 줄어든다. 서버(serializer)와 내보내기(`dataset_manager/bindings.py`, `formats/coco.py`)도 자르지 않는다. 결과적으로 경계 밖 좌표가 DB와 export 결과에 그대로 남는다.

## Key Decisions

- **편집 중에 막는다, 나중에 자르지 않는다.** 이번 범위의 편집은 사용자가 보는 모양과 저장되는 모양이 같아야 한다. 경계에 닿은 순간 화면에서 멈추게 한다. 범위 밖 편집(사각형 핸들 크기 조절, 그 외 도형)은 현행 `fitPoints` 보정을 그대로 둔다.
- **범위는 스켈레톤(bbox·키포인트) + 사각형 통째 이동.** 사각형 통째 이동은 지금 "놓을 때 잘려 줄어드는" 문제가 있어 같이 고친다. 그 외 도형(회전 사각형, 폴리곤, 폴리라인, 포인트, 타원, 큐보이드, 마스크)은 이번 범위가 아니다. 사용자 결정 2026-11-04.
- **키포인트는 경계에서 멈춘다.** 경계 밖으로 끌어도 자동으로 `outside` 처리하지 않는다. 사용자 결정 2026-11-04.
- **통째 이동은 크기를 유지한 채 멈춘다.** 잘라서 줄이지 않는다. 축별로 따로 멈추므로, 왼쪽 벽에 닿은 상태에서도 위아래로는 계속 움직인다. 사용자 결정 2026-11-04.
- **기존 데이터는 그대로 둔다.** DB 마이그레이션, export 시 클리핑 모두 하지 않는다. 사용자 결정 2026-11-04.
- **포즈 모양은 깨지 않는다.** 여러 개를 함께 옮기거나 스켈레톤을 회전할 때, 하나라도 경계에 닿으면 전체가 그 자리에서 멈춘다. 개별 점만 경계에 눌려 포즈가 찌그러지는 일은 없다. 가정(사용자 확인 대기) — Q1, Q2.

## Actors

- A1. 어노테이터: 스켈레톤·사각형을 그리고 고친다.
- A2. 검수자: Standard 모드에서 같은 편집을 한다. 동작 차이 없음.

## Requirements

용어: "이미지 경계" = x는 0~이미지 너비, y는 0~이미지 높이(현행 `fitPoints`와 같은 범위, 경계값 포함). "범위 내 객체" = 스켈레톤과 회전 없는 사각형.

**스켈레톤 bbox**

- R1. bbox 모서리·변 핸들로 크기를 바꿀 때, 핸들은 이미지 경계에서 멈춘다. 기존 규칙(bbox가 보이는 키포인트를 모두 포함)도 계속 지킨다.
- R2. 새 스켈레톤을 그릴 때 자동 생성되는 bbox(키포인트 범위 ±20px)는 이미지 경계에서 잘린다. 가장자리 쪽 여백만 줄고 반대쪽 여백은 20px 그대로다.
- R3. 키포인트를 옮겨 bbox가 자동으로 넓어질 때(soft-snap), bbox는 이미지 경계까지만 넓어진다.
- R4. bbox가 비어 있는(`[]`·`[0,0,0,0]`) 기존 스켈레톤을 열 때 만드는 대체 bbox(±20px)도 R2와 같이 이미지 경계에서 잘린다. 저장된 bbox가 없어 새로 만드는 값이므로 R17(기존 데이터 유지)와 충돌하지 않는다.

**키포인트**

- R5. 키포인트 하나를 끌 때, 이미지 경계에서 멈춘다.
- R6. 새 스켈레톤을 그릴 때, 그리는 사각형은 이미지 경계까지만 늘어나고 템플릿 키포인트는 그 사각형 안에 배치된다. 그리는 중 미리보기도 같은 모양이다. 가정(사용자 확인 대기) — Q5.
- R7. 스켈레톤 회전으로 키포인트 하나라도 경계에 닿으면 회전이 그 각도에서 멈춘다. 회전 중 미리보기도 같은 각도에서 멈춘다. 가정(사용자 확인 대기) — Q2.

**통째 이동**

- R8. 스켈레톤 하나를 통째로 끌 때, bbox가 이미지 경계에 닿으면 그 축으로 멈추고 크기·포즈는 그대로다. bbox 밖에 있는 `outside` 키포인트도 함께 옮겨지되 이미지 밖으로는 나가지 않는다.
- R9. 사각형(회전 없는)을 통째로 끌 때, 경계에 닿으면 그 축으로 멈추고 크기는 그대로다. 놓은 뒤에도 크기가 줄지 않는다.
- R10. 여러 객체를 선택해 함께 끌 때(멀티 드래그), 범위 내 객체 중 하나라도 경계에 닿으면 그 축으로 묶음 전체가 멈춘다. 범위 밖 도형은 멈춤 판정에 끼지 않고 지금처럼 함께 움직인다.
- R11. INNO-156/157의 Shift+드래그로 여러 키포인트를 선택해 함께 옮길 때도 R10과 같이 묶음 전체가 멈춘다. 이때 늘어나는 bbox는 R3을 따른다.

**드래그 중 손맛**

- R12. 끄는 대상의 위치는 항상 "커서 위치 − 잡은 지점 오프셋"을 이미지 경계로 자른 값이다. 커서가 밖에 있는 동안 대상은 경계에 붙어 있고, 커서가 다시 잡은 지점 기준 위치로 돌아오면 튀지 않고 바로 따라온다. 축별로 독립이다.
- R13. 경계에서 멈출 때 알림·경고 메시지나 별도 시각 표시는 없다. 멈추는 것 자체가 피드백이다.
- R14. 커서가 캔버스나 브라우저 창 밖으로 나가도 드래그는 이어지고, 그 밖에서 버튼을 놓아도 드래그가 정상 종료된다.
- R15. 위 동작은 annotation 모드와 interpolation(track) 모드 모두에 적용된다. track은 편집 중인 프레임의 값에만 적용한다.
- R16. 되돌리기 단위는 지금과 같다. 경계에서 멈춘 드래그도 한 번의 Undo로 되돌아간다.

**기존 경계 밖 데이터**

- R17. 이미 경계 밖에 저장된 객체는 열거나 저장해도 자동으로 안으로 옮기거나 자르지 않는다.
- R18. 그런 객체(또는 그 키포인트·핸들)를 끌면, 잡는 순간 튀지 않는다. 지금 위치보다 더 바깥으로는 못 가고, 안쪽으로는 자유롭게 움직인다. 멀티 드래그에서도 그 객체는 이미 나가 있는 방향으로만 묶음을 막는다. 가정(사용자 확인 대기) — Q3.
- R19. 경계 밖 사각형을 통째로 끌어 놓았을 때, 여전히 일부가 밖에 있어도 잘리지 않고 크기가 유지된다.
- R20. 보이는 키포인트가 이미 경계 밖에 있는 스켈레톤은, 그 방향의 bbox가 "키포인트 포함" 규칙을 우선한다. bbox는 그 키포인트까지는 나가 있을 수 있지만 더 나가지는 않는다.

## Acceptance Examples

- AE1. 1920×1080 이미지, 오른쪽 끝(x≈1905)에 사람 스켈레톤을 그림 → bbox 오른쪽 변이 x=1920. 왼쪽 여백은 20px. 키포인트는 모두 x≤1920. (R2, R6)
- AE2. bbox 오른쪽 아래 핸들을 이미지 밖으로 끌어냄 → 핸들이 이미지 모서리(1920, 1080)에서 멈춤. (R1)
- AE3. 손목 키포인트를 이미지 왼쪽 밖으로 끌어냄 → 키포인트가 x=0에 멈추고 `outside`로 바뀌지 않음. bbox 왼쪽 변도 x=0까지만 넓어짐. 커서를 다시 안으로 가져오면 키포인트가 튀지 않고 따라옴. (R3, R5, R12)
- AE4. 300×200 사각형을 왼쪽 위로 끌어 화면 밖까지 → 사각형이 (0,0)에 붙어 멈춤. 놓은 뒤에도 300×200. 계속 아래로 끌면 왼쪽 변은 x=0에 붙은 채 아래로 움직임. (R9)
- AE5. 사람 두 명과 폴리곤 하나를 멀티 선택해 오른쪽으로 끔 → 오른쪽 사람의 bbox가 x=1920에 닿는 순간 셋 모두 멈춤. 두 사람 간격 그대로. (R10)
- AE6. Shift+드래그로 오른팔 키포인트 3개 선택 후 오른쪽으로 끔 → 가장 오른쪽 키포인트가 x=1920에 닿으면 3개 모두 멈춤. 한 번의 Undo로 원위치. (R11, R16)
- AE7. 예전에 bbox가 x=-15까지 나간 채 저장된 스켈레톤 → 열어도 그대로 -15. 내보내기에도 -15. 그 스켈레톤을 오른쪽으로 끌면 튀지 않고 정상 이동하고, 왼쪽으로는 더 못 감. (R17, R18)
- AE8. 왼쪽이 x=-30까지 나간 기존 사각형을 오른쪽으로 10px만 끌어 놓음 → x=-20에서 시작, 크기 그대로. (R19)
- AE9. 가장자리 스켈레톤을 회전 → 어깨 키포인트가 x=1920에 닿는 각도에서 회전이 멈춤. 포즈 모양 그대로. (R7)

## Success Criteria

- 이 기능 배포 후 직접 그리거나 편집한 스켈레톤의 bbox·키포인트에 이미지 경계 밖 좌표가 새로 생기지 않는다(기존 경계 밖 데이터와 붙여넣기·프레임 전파·가져오기는 제외).
- 가장자리로 옮긴 사각형이 놓은 뒤 줄어드는 현상이 없다.
- 경계 안에서의 편집 동작(드래그 감도, 핸들, soft-snap, Undo)에 회귀가 없다.

## Scope Boundaries

- 회전 사각형, 폴리곤, 폴리라인, 포인트, 타원, 큐보이드, 마스크의 경계 제한. 이들의 편집 시 보정 동작은 지금 그대로다.
- 사각형 크기 조절(핸들) 경계 제한. 지금처럼 놓을 때 잘린다. 가정(사용자 확인 대기) — Q4.
- 기존 경계 밖 데이터의 일괄 보정(마이그레이션), export 단계 클리핑.
- 서버(serializer) 측 경계 검증.
- 붙여넣기(Ctrl+V), 프레임 전파(propagate), 가져오기(import)로 들어오는 좌표의 경계 제한. 후속 과제로 남긴다.

## Outstanding Questions

### 가정한 기본값 (계획은 기본값으로 진행, 구현 전 사용자 확인)

- Q1. 멀티 드래그 시 "묶음 전체 멈춤"(기본값) vs "각자 경계에서 따로 멈춤"(모양이 찌그러짐).
- Q2. 회전으로 키포인트가 경계에 닿을 때 "회전 자체가 그 각도에서 멈춤"(기본값, 포즈 유지) vs "해당 키포인트만 경계에 눌림"(포즈 변형).
- Q3. 기존 경계 밖 객체를 끌 때 "바깥으로만 막고 안쪽은 자유"(기본값) vs "잡는 순간 안으로 끌어들임".
- Q4. 사각형 핸들 크기 조절도 경계에서 멈추게 할지. 기본값은 범위 밖(현행 유지).
- Q5. 가장자리에서 새 스켈레톤을 그릴 때 "그리는 사각형이 경계까지만 늘어나고 키포인트는 그 안에 배치"(기본값) vs "템플릿 크기 유지, 통째로 안쪽으로 밀어 넣음".

### Deferred to Planning

- 경계 제한을 드래그 라이브러리 제약(svg.draggable의 min/max)으로 걸지, 이동 핸들러에서 직접 보정할지. svg.draggable 2.2.2의 min/max는 절대값이라 기존 경계 밖 객체를 첫 이동에 안으로 튀게 한다(R18 위반). 쓰려면 경계를 드래그 시작 위치 기준(`minX = min(0, 시작 xtl)` 등)으로 매번 계산해야 한다.
- 멀티 드래그는 주 객체의 이동량으로 나머지를 옮기므로(`moveShapeVisually`), 묶음 전체의 범위를 이동 핸들러에서 계산해야 한다.
- ±20px 대체 bbox 계산은 shape 생성자와 track 쪽 여러 곳(keyframe 로드, 저장 시 soft-snap, 조회 시 `resolveBbox`)에 흩어져 있다. R2·R4 경계 자르기는 모두에 똑같이 적용해야 프레임 간 값이 어긋나지 않는다.
- R19을 위해 사각형 통째 이동 반영 시 `fitPoints` 자르기를 건너뛰는 방법.
- 프레임마다 이미지 크기가 다른 task에서 경계 기준(프레임별 `framesInfo` vs 캔버스의 현재 이미지 geometry, offset 포함)과 좌표 반올림.
- 새 스켈레톤을 그릴 때 사용자가 그린 사각형을 bbox로 쓸지(현재 drawHandler는 그린 사각형을 bbox로 넘기지 않음). 이번 요구는 결과 bbox가 경계 안에 있는 것만 정한다.
